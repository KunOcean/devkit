# DevKit 版本与协作规范

面向 API / Agent 场景的 **DevKit 版本与协作**规范。

| 文件 | 内容 |
|------|------|
| `references/spec-prompt.md` | 《版本与协作规范》全文——协作流程、版权声明、版本架构、语言变体后缀、双版本派生、代码风格、已废弃概念、版本结构文字表述与版本结构图规则 |
| `references/prompt-templates.md` | 4 个版本相关模板：版本规划、版本号推导、多语言适配、完全重写 |

## 何时使用

- 用户要求按 DevKit 规范产出或改动代码（版本号、版权注释块、双版本派生）
- 用户要求推导下一个版本号、规划版本演进路径
- 用户要求绘制版本结构图（Mermaid 整略图 / Mermaid 完整图 / HTML 版本结构图）
- 用户要求 `_CN` / `_GLOBAL` 双版本派生或多语言适配

## 使用方式

1. **先判断类别**：规范类 → 读 `references/spec-prompt.md`；模板类 → 读 `references/prompt-templates.md`
2. **只读需要的那个文件**，不要两个都读
3. **模板类**：按 `id` 定位模板，把具体需求与代码代入，沿用其结构与措辞
4. **规范类**：作为本次对话的硬性约束实际执行

## 不可违反的要点（摘录，完整内容见 references）

- **版本号**：四层基础（分支代号 / 罗马数字 / Φ+数字 / 英文标识）＋ 循环扩展（`B1 → I → Ψ1 → 英文标识 → C1 …`）；语言变体共享主干版本号，仅在末尾追加 `_CN` / `_GLOBAL`
- **双版本派生**：落后版一律以领先版同一主干版本为源翻译派生；禁止"基于自己上一版独立迭代"；禁止全文重译
- **协作**：改动前先给出确认表格（我理解你需要我做什么 / 我将会怎么做，含新版本号），再用交互式提问工具（如 AskUserQuestion）请用户拍板，确认后才动手；auto / 无人值守模式下跳过事前确认，改为事后补同样格式的汇报表
- **提问**：遇歧义、多方案取舍、各有权衡的选项时，主动用交互式提问工具问清，不得替用户决定；一次问完，不要挤牙膏
- **同步**：每次改动完成后主动询问是否同步到 GitHub（立即同步 / 只提交 / 暂不同步）；推送必须经用户明确选择后才执行，不得自行推送
- **记忆**：未经用户明确要求，不得写入长期记忆或持久化载体（记忆文件 / MEMORY.md / CLAUDE.md 等）；确需写入先说明写什么、写到哪里，确认后再写
- **已废弃概念**：智能应用引擎 / AI 输出指令协议、"指令修改版"选项、落后版独立迭代模式——不得恢复
